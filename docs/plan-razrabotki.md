План разработки HobbyLife для ИИ-агентов

Как пользоваться: задачи выдаются агентам строго по порядку (зависимости указаны). Каждой задаче агенту передаётся: (1) текст карточки задачи целиком, (2) указанные в карточке разделы ТЗ (tz-internet-magazin.md), (3) актуальный код репозитория. Задача считается принятой только при выполнении всех пунктов Definition of Done (DoD). Один агент — одна задача — одна ветка — один PR.

Общие правила для всех задач (включать в каждый промпт агенту):

Монорепозиторий: backend/, frontend/, docker-compose.yml, docs/.
Backend: Python 3.12, FastAPI, SQLAlchemy 2.0 async, Pydantic v2. Стиль: ruff (line-length 100), mypy для сервисного слоя. Роутеры не содержат бизнес-логики и не обращаются к БД напрямую — только сервисы.
Frontend: Next.js App Router, TypeScript strict, Tailwind. Никаких ценовых вычислений на фронте.
Деньги: Decimal / NUMERIC(12,2). Валюта — KGS, формат 1 250 сом.
Каждая задача с изменением схемы БД включает Alembic-миграцию (upgrade + downgrade, проверенные с нуля).
Каждая задача включает тесты на новую функциональность; существующие тесты не должны падать.
Не выдумывать API платёжных провайдеров: до получения реальных доступов используется только MockPaymentProvider.
Секреты и настройки — только через ENV (pydantic-settings); в репозитории — .env.example.
Каждый PR обновляет docs/CHANGELOG.md (1–3 строки) и, при изменении API, автогенерируемую OpenAPI-спеку не редактирует руками.
